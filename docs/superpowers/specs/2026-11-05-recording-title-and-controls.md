# 手机录音页标题与后台控制

用户截图显示正在录音时没有标题、转写区有多层滚动，锁屏仅有返回录音页的普通通知。保留现有手机首页、录音与保存流程，修正官网实时记录页的适配。

## 标题与正文

官网录音时使用 CdJi 的 `input#record_title`；之前的回归只渲染 ytgv 的 readonly 标题。原有移动端纵向 flex 使可编辑组件自身的 `width:0; flex:1` 收缩到16像素，内部桌面头部的88像素高度也会裁掉编辑标签。适配真实输入框的容器宽高、头部中间层以及48像素触摸区域。标记“录音标题 · 点击修改”，键盘完成或失焦继续触发官网原来的 onBlur/onTitleChange 保存，不新增改名接口或本地副本。

官网 ARw7 将编辑器设为 `calc(100vh - 197px)` 高、`calc(100% + 49px)` 宽并左移22像素。手机卡片有自己的固定视口，外层另设 overflow:auto 会产生两层滚动。让编辑器填满手机卡片，外部容器裁切溢出，正文滚动由官网编辑器内部容器负责。

## 后台录音控制

实际麦克风轨道与官网录音控件共同决定状态。采音预检查不产生录音会话。脚本在状态、标题、网络提示变化时发送快照；录音计时变化最多每15秒同步一次，不新增定时器或页面心跳。通知用系统计时器展示时间。

通知显示当前标题、录音/暂停状态与可恢复网络异常提示。暂停命令点击官网的暂停按钮，重复暂停不反向切换；继续命令先通过 PendingIntent 打开可见录音页，再点击官网继续按钮。麦克风前台服务只在实际采音时运行，暂停释放前台状态和息屏 CPU 唤醒锁并保留继续入口。结束仍走官网确认/保存流程。

小米使用官方焦点/超级岛通知格式；不创建悬浮窗，不把录音伪装成媒体播放。小米要求开发者服务开通、App ID、签名证书及场景/上线审核，项目目前缺少这些外部前提。默认包使用普通通知，只有配置了获批的 App ID、设备支持且系统焦点权限开启时，才附带原生岛参数。App ID 从构建参数或环境变量注入，不使用虚假或其他应用的 ID。

## 网络提示的含义

官网 `handleConnectFail` 的 `couldRecovery` 分支设置 `sessionState.holding` 并提示网络不稳、继续录音。`handleConnectRecovery` 清除 holding 并提示恢复转写。截图只说明当时进入这个可恢复分支，不能证明完整音频已保存，也不能确定是网络本身还是息屏网络限制触发。客户端不绕过官网连接控制或伪造转写成功。

## 验证

- 本地回归覆盖320/390/412像素的实际标题结构与编辑器偏移，键盘完成、暂停/继续幂等和网络提示状态。
- 官网组件集成使用真实 CdJi/ytgv 标题输入与事件处理器、本地文档上下文，不登录账号、不创建云端会议。
- 签名正式 APK 在隔离安卓模拟器验证标题到通知同步、系统通知暂停真实麦克风与继续回到同一录音页。
- 检查息屏编码继续、暂停资源释放及结束返回，保持既有播放功能回归。
- 未连接用户的小米真机，不能将模拟器结果当作小米原生岛渲染或实际网络质量的证明。
