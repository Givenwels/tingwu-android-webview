# 分类续页与息屏录音

用户目标：文件夹中能继续向下查看全部分类记录；息屏后持续使用麦克风录音，同时约束耗电及不必要的后台行为。

分页根因：客户端将 null 总数当作零、忽略 totalNum，并假设无总数时每页一定返回 20 条；注入的列表又受到官网内层列表裁切。修复按需续页、总数兼容、空页与重复页终止、独立可滚动面板和可触达的“加载更多”。没有预取全量记录或定时轮询。

录音根因：旧版只有 keepScreenOn，没有后台麦克风前台服务。麦克风预检查与真正录音分开，只有实际采音且官网已进入录音控制状态时，启动非导出的 microphone 前台服务和可见通知。遵循 [Android 麦克风服务要求](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone)，从前台创建服务，既有系统麦克风授权必须有效。服务不自行开启麦克风，不重启恢复采音。

耗电边界：删除强制亮屏；仅在实际录音且息屏时持有带超时的 PARTIAL_WAKE_LOCK，亮屏立即释放。暂停、结束、页面离开、Activity 销毁或渲染进程退出后停止录音服务。服务 START_NOT_STICKY，不开机自启，不请求高性能 Wi-Fi 锁、省电白名单、悬浮窗或无障碍。官网仍收到真实的页面可见状态。

验证包括分页短页/缺失总数/裁切/错误重试与实际官网 H5 布局，以及对正式录音 Activity 的系统授权、真实官网 Opus 编码、持续 70 秒息屏、暂停/继续/结束及通知和资源释放。测试数据和静音输入留在隔离浏览器或模拟器中，不登录用户账号，不创建云端会议。真机耗电与小米安全中心判定不能由模拟器替代。
